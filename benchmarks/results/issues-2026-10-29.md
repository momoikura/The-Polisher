# Benchmark: 17 open issues from 10 popular Python repos (2026-10-29)

**Question:** on real, open GitHub issues, how often does ThePolisher produce a
fix that its own new tests *prove* in the sandbox, compared with a single prompt?

**Proven** means the new tests fail on the original code and pass with the patch
(the sandbox's fail-to-pass check), with no other check failing because of the
patch. The single-prompt number is the same check on the first draft each run
starts from: same model, same issue, one prompt, no review loop.

## Result

| | ThePolisher | Single prompt |
|---|---|---|
| **Fix proven, all 17 issues** | **14 (82%)** | 7 (41%) |
| **Fix proven, the 12 issues never seen before** | **10 (83%)** | 5 (42%) |
| Unproven first draft turned into a proven fix | 7 | |
| Proven first draft made unproven | 0 | |
| All four agents signed off (status "clean") | 4 | |
| Total model cost, 17 issues | $0.66 | |
| Median cost / time per issue | $0.040 / 10.8 min | |
| Longest run | 50 min | |

## How it was run

- **Issues chosen before any run** and committed first
  ([`issues-2026-10-29.json`](../issues-2026-10-29.json), commit `63b9523`):
  open, filed 2026-08-01 or later, no linked pull request, a reproducible bug in
  library code still present in the current code. Excluded: features, docs,
  refactors, CI, typing-only, performance, spam, and issues already shown fixed
  or intended. Of 72 recent issues searched, 17 qualified. Each was run once and
  every result is kept.
- Model **muse-spark-1.3-contributor**, budget **$0.50** per issue, two issues
  at a time, settings as deployed on 2026-10-29 (no time limit yet).
- Harness: [`run-benchmark.mjs`](../run-benchmark.mjs). Raw results:
  [`issues-2026-10-29.jsonl`](issues-2026-10-29.jsonl). No pull requests were opened.

## What it doesn't show

- 17 issues is a small sample; the percentages will move with more.
- Costs are model tokens only (not the Modal sandbox).
- The 3 unproven issues: pyparsing#693 (the regression is likely in a 255 KB file,
  over the 200 KB limit), astroid#3255, and pygments#3247 (a ReDoS fix needs a
  timing test, and each sandbox check ran the whole suite; 50 minutes). Runs now
  stop at 20 minutes and keep the best version.
- Hard issues are slow: median 10.8 minutes, mostly waiting on whole-suite test
  runs in the sandbox.

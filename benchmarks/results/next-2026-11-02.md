# Formatters and large files, 2026-11-02

Two changes, each checked once ([list](../next-2026-11-02.json), [results](next-2026-11-02.jsonl)).

## The project's own formatter

The final whole-suite run now runs a project's black, isort or ruff format on the changed files, when the project's dependencies installed it. It skips any file the formatter would also change on the original code, so a PR never reformats lines it didn't touch.

On invoke's PR, which failed its style check before, I sent the original unformatted commit through it:

- **It found and ran invoke's Black,** and formatted the new test file.
- **It skipped `invoke/__init__.py`, the file that failed CI.** The sandbox installs the newest Black (26), but invoke's CI uses Black 25, and Black 26 would also reformat the original file. So the safety rule kept it out, and that PR would still have failed its style check.

It helps when the sandbox gets the same formatter version as a project's CI, and it does nothing harmful when it doesn't. It doesn't yet find the version a CI uses. A fresh run of invoke#1066 was clean and proven, with no new failures, for $0.09.

## Files up to 900 KB

The agents now edit Python files up to 900 KB, up from 200 KB, through excerpts and exact edits. pyparsing#693, whose code is in a 249 KB file, used to stop after planning. Now it runs, but it isn't proven: it changed a different file, and its test never passed. This shows the hard stop is gone, not that fixes in large files work.
